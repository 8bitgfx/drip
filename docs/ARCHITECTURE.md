# Architecture

Every file has one home. The plugin parts sit where Claude Code and Codex expect them; everything the server
reads or copies is in `content/`; the server itself is in `mcp/`.

```
drip/
  README.md            for users: what it is, install, commands, links to docs/
  AGENTS.md            for coding agents working on Drip (CLAUDE.md-style rules and gotchas)
  CHANGELOG.md         what each release changed
  CREDITS.md, LICENSE

  .claude-plugin/      plugin.json (Claude Code manifest; starts node mcp/dist/drip-mcp.mjs inline), marketplace.json, icon.png
  plugin.json          portable manifest for the native Codex plugin (hooks: hooks/codex-plugin.json)
  mcp.json             launches the shared bundle for Codex
  .agents/plugins/     marketplace.json (Codex install source)
  .github/workflows/   ci.yml: lint, build, stale-bundle check, tests on Linux + Windows; manifest versions agree

  skills/              drip (director) + drip-<craft>; each SKILL.md + guide.md + reference/ (served by drip_guide)
  agents/              builder, critic, helper, checker, scout (Claude Code subagents; model in the frontmatter)
  commands/            /drip:ui, /drip:logo, /drip:motion, /drip:critic, /drip:adapt, /drip:settings
  hooks/               hooks.json + Node scripts (gate, recorder + lint, stop guard, prompt nudge, claims, film)
    hosts/             hook adapters: translate Codex / Cursor / OpenCode payloads to the hooks above

  content/             what the server serves or copies (paths in mcp/src/core/paths.mjs)
    rules/             shared rules, served as drip_guide rules/<x>

    data/              catalogue.json, pieces.json, font-pairs.json, slop.json

                       brand-board.html (board_brand), readme-art.mjs, system.html
    film-viewer/       the Drip Film page drip_film copies next to film.json

  mcp/
    package.json       scripts: build, build:hosts, test, smoke, lint, check

      gen/             providers/ (openai, gemini, template), keypage, settings page
```

## How enforcement works

1. **State.** `<project>/.drip/state.json` holds one task PER SESSION (`tasks`, `sessions`): the loop size,
   required guides and which were read, references studied, the board and chosen direction, UI writes, fit-check
   results. The server (one per Claude session) remembers its task and its `CLAUDE_CODE_SESSION_ID`; hooks get
   `session_id` from Claude Code; `hooks/bind.mjs` binds a session to the task its `drip_start` created. A session
   never sees, gates on, records into or closes another live session's task; a task whose session is gone is
   picked up by the next one.
2. **Guides through a tool.** `drip_guide` returns a guide and records the read. Skill files hold only the
   first-screen rules; the depth lives behind the tool call, so "I read the skill" can be checked.
0. **Opt-in.** With `gates.mode: "task"` (default) every hook is silent unless a Drip task is open
   (`/drip:ui` → `drip_start` … `drip_end`). `"always"` makes the gate apply to every UI write.
3. **Gates in hooks.** `hooks/pre-write.mjs` runs before Write/Edit. For UI files it computes what is missing
   (`missingBeforeUi` in `core/state.mjs`) and denies with the exact next call. Logic-only edits pass.
4. **Recording + lint.** `hooks/post-write.mjs` records UI writes and lints the file (rules in `content/data/slop.json`),
   feeding problems back to Claude immediately.
5. **No finishing without looking.** `hooks/stop.mjs` blocks the end of a turn when UI changed after the last
   fit check (max 3 blocks in a row, then it lets go).
6. **Nudges.** `hooks/prompt.mjs` and `hooks/session-start.mjs` add one line of context so Claude calls
   `drip_start` without being told.

Hooks import the dependency-free parts of `mcp/src/core` directly (`paths`, `config`, `state`, `evidence`, `skills`, `film`, `jsonstore`, `util`, and `modules/fitcheck/lint.mjs`), so the server and hooks share one source of truth. Keep those files on Node built-ins only.

## Sources of design data

| Need | Source | Key |
|---|---|---|
| References | Dribbble web-client endpoints (XHR fragments + embedded shot JSON), throttled ~1 req/s, cached | none |
| Components | shadcn-style registries (`/r/registry.json`) + shadcn's registry directory | none |
| Icons | Iconify public API | none |
| Fonts | Fontsource API; specimens via Google Fonts CSS | none |
| Photos | Wikimedia Commons; Unsplash, Pexels (free keys); Openverse | optional |
| Image generation | OpenAI, Gemini, custom adapters | user's own |
| Screenshots / previews | the user's Chrome or Edge, headless | none |

## Adding a reference source

Write `mcp/src/modules/refs/<source>.mjs` exporting `listing()` and `shot()` with the same shapes as
`dribbble.mjs`, then register tools for it in `refs/index.mjs`. Keys in `seen` are `<source>:<id>`, so boards
and contact sheets work unchanged.

## Roles: the director and its crew (Swarm Mode)

Swarm Mode is the same design loop with the work split by cost. The director (the session's own model) keeps the decisions and a small
context; cheap subagents do the reading, building and measuring. Gates, state and evidence are unchanged: the crew uses the same tools.

| Agent | File | Model | Does | Returns |
|---|---|---|---|---|
| Scout | `agents/scout.md` | Haiku | `refs_site` / `refs_search` / `refs_gallery` for ONE role, drops cookie and bot pages, calls `refs_study` with the role | top 3, five-line study each |
| Builder | `agents/builder.md` | Sonnet | builds the sections in its brief (one to a few) from the director's specs on the named library pieces | changed files |
| Helper | `agents/helper.md` | Haiku | one small mechanical job (install pieces, save images, swap copy, run one check) | what it changed |
| Checker | `agents/checker.md` | Haiku | `fitcheck_shot` with `numbersOnly` (or `section`), per section | blockers and numbers only |
| Critic | `agents/critic.md` | Sonnet | independent review (not part of this module) | verdict, scores, fixes |

### Tools (module `mcp/src/modules/swarm`)
- `build_prepare` and `critic_prepare` write each brief to `.drip/briefs/` (`core/briefs.mjs`) and return a two-line `Agent({ subagent_type: "drip:<agent>", ... })` call that names the file. At most two builders: `groupSections` gives one builder up to three sections, two beyond.
- `scout_prepare` and `checker_prepare` still exist (reachable through `drip_search` / `drip_execute`) but the fast loop uses no scouts or checkers.
- `swarmInstructions(task, { env })` is the short block `drip_start` shows in swarm mode. It says so when the host does not launch Drip's named subagents.
- `swarmOn(config, task)`: builders are on unless the config has `swarm: false` (default true, the Builders switch on the settings page) or the task says otherwise.

### Hosts
Claude Code (and the Cowork plugin) load `agents/*.md` from the plugin, model in the frontmatter. Other hosts are not given the swarm agents:
they fall back to the single-agent loop, which the `*_prepare` tools still support (see [HOSTS.md](HOSTS.md#swarm-mode-without-subagents)).

The roles are in `skills/drip/fast.md` (Roles; `drip_guide fast`).

## Drip Film: watch the swarm build

A Drip task records the story of the work: the references, assets and pieces before building, who did what and where on the page, and frames of the whole page as it is built. The user watches it live (it opens at `drip_start`) and gets a montage at the end, in any IDE: the viewer is a static page Drip serves on localhost. The recorded format: [FILM.md](FILM.md).

### Pieces

| Part | Where | What |
|---|---|---|
| Events | `hooks/agent-start.mjs`, `agent-stop.mjs`, `post-write.mjs`, `film.mjs` | Append-only lines in `.drip/film/<task>/events.jsonl`: a subagent's start (type, label, section, piece from its brief), its end (SubagentStop), every UI write and every Drip tool call, each with the `agent_id` Claude Code puts on hook input (`main` for the director); writes carry hints for where they land. Hosts without these hooks: the server logs its own tool calls (`registry.mjs`, `filmed`). |
| Process | `mcp/src/modules/film/record.mjs` (`filmRecord`, `filmAsset`) | References (`refs_site`, `refs_gallery`, `refs_study`), assets (`images_save`, `gen_image`, `art_generate`, `mockup_render`) and pieces (`pieces_preview`, `pieces_install`) as events with thumbnails in `thumbs/`. |
| Frames | `mcp/src/modules/film/index.mjs` (`tick`, every 5 s in server mode) | When the page changed (a write or stitch) and at most every 12 s, the whole page at 720 px wide into `frames/`; error overlays, blank and loading pages are skipped. Each frame also places the pending writes (`targets.json`). |
| film.json | `mcp/src/core/film.mjs` (`buildFilm`) | Agents (a start is matched to the first unseen `agent_id` of its type), events and frames (each frame knows who was working). The one file the viewer reads. Contract: `version`, `task`, `agents[]`, `events[]`, `frames[]`. |
| Viewer | `content/film-viewer/` (`model.js` story, `viewer.js` page; DESIGN.md) | The run as a story: references, then pieces and assets, then the page built in one window with a cursor per agent, a finished card over the last frame. Live follows the head of the run. Blank, error-overlay and unchanged frames are skipped; old films play without refs and cursors. `drip_film` copies it next to film.json and serves the folder; without it a small built-in viewer is used. |
| Montage | `finishFilm` at `drip_end` | A last frame, `endedAt`, the link in drip_end's reply, and `montage.mp4` when ffmpeg is on PATH. |

Turn it off per task with `task.film = false`.
