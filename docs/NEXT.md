# Next session: open problems (updated 2026-11-26, Drip 0.9.0)

## Done in 0.9.0: cost
The anime run's 28.5M tokens were the director's context (83k at the start, 411k at the end) re-read on each of 116 calls. Cost = calls x context, so 0.9.0 cuts both:
- **Briefs in files** (`core/briefs.mjs`): `build_prepare` and `critic_prepare` write each brief to `.drip/briefs/` and return a two-line launch call. Before, a builder brief sat in the director's context twice (tool result, then the Agent call).
- **Fewer pictures, smaller**: fast loop fit checks show one small sheet per size the first time the page is seen (`fitcheck.seenAt`), numbers only after that (still recorded as the check); `refs_site` gives one 960px sheet per site instead of every screen; piece previews are 960px wide.
- **One fix list**: after 6 edits by the director since the last page check (`directorEdits`, reset by fitcheck_shot and build_prepare), the write gate asks for one list: a SendMessage to the builder that wrote the section, or one MultiEdit.
- **No scouts or checkers in the fast loop**; helpers only for long mechanical jobs; installs and downloads are tools.
- **Critic optional in the fast loop** (`gates.fastCritic`, default false): offered in the hand-off, not required by `drip_end`. A REVISE it gave still needs the user's choice.
- **Retries inside tools**: `pieces_install` retries registry timeouts twice; `fitcheck_shot` retries once when the page reloads under it.
- **All gaps at once**: `drip_status`'s NEXT lists everything missing, not the first item.
Not measured yet: re-run the anime studio prompt and compare calls, peak context and total with the 0.8.21 run (116 calls, 411k peak, 28.5M).

## Done in 0.8.22 (from the 2026-11-25 "AI animation studio" run)
What the transcript showed (`~/.claude/projects/C--Dev-drip-lab/df2920a1-…jsonl`, 25 min, 17 builder launches, ~28.5M cache-read tokens in the main session):

Codex built the product (an editor with viewport, timeline, motion settings); Drip built a marketing page about it. Now a product named with what it does ("a <studio|workspace|generator|…> for <doing X>") is surface `app`, and `drip_start` tells the director to design the product's main screen, with "its landing page" as a question when in doubt (`guess` in `modules/workflow.mjs`).
- **False "NEW ROUND".** Every new round in that run came from task notifications (a builder's or the critic's report with "generic", "template", "boring"), never the user. They forced two extra look rounds, five blocked writes and the full 7-builder rebuild after the critic's REVISE. The critic did not ask for a redo: it listed five fixes, and the director was fixing them when the hook demanded a new round. `hooks/prompt.mjs` now reads only the user's own words (`userWords` in `hooks/transcript.mjs`).
- **The director handed the task to a new session.** Cause confirmed: the Cubism session's own reasoning quotes the memory ("my notes say Drip test sessions should start there"). The memory is corrected; nothing in Drip suggested sessions. `swarmInstructions` and `fast.md` now say the director never hands the task to another session.
- **Builders capped at 2.** `build_prepare` groups sections (one builder up to 3 sections, two beyond; nav/hero/footer, which share index.html, stay with one builder; a whole-page build is one builder). `groupSections` in `modules/swarm/index.mjs`.
- **Critic before the page was finished.** The first critic ran while the footer builder was still writing. `critic_prepare` (kind build) refuses while a builder is running.
- **Wrapper files for the piece check.** efferd's `header3` installs `header.tsx`, so "piece not on the page" fired and the director wrote re-export files. `pieces_install` now records each registry item's real file names (`task.pieceFiles`) and the check accepts them.
- **Codex shell gate.** `pre-shell.mjs` now runs for Codex's shell tool (`Bash|shell|exec_command|local_shell|shell_command|unified_exec`, string or argv commands). `hooks/codex-plugin.json` (the root plugin's hooks) is generated by `build:hosts` and checked, so it no longer drifts.
